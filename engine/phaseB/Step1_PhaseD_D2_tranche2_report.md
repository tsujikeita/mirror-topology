## 2. 生成器 core（`d2_bank.generate_configuration_bank`／`verify_bank_dir`）
- 1 配置（または family reference）× 1 batch を family の evaluation latent（`generate_from_latent`，key からの replay）で走査し，shard ごとに atomic `.npz`（role×selection の T1/T2/AX/PL＋cid）と sidecar（identity・row／cluster／rotation 範囲・UID 端・root SHA・cov SHA・表／仕様 SHA・array SHA・file SHA・環境・dtype・scale／formal）を書き，最後に完了 manifest（`COMPLETE.json`；manifest SHA）を確定。
- **fresh attempt**：出力先が存在すれば拒否。**完成 cache の再利用**は `verify_bank_dir` のみを経由：manifest SHA・全 shard の file／sidecar bytes・全 array SHA を読込み配列から再計算・行範囲の連続性・dtype（T1/T2 f64・AX/PL int32）・有限性；完了 manifest のない partial や改変 array／sidecar は拒否。
- roles は配置（3 role）／reference（ref_matched のみ）に限定；`scale<1` は self-test 専用で sidecar／manifest に `formal=False` を記録。
- 試験（`tests/test_d2_tranche2.py` 2 件；TEST-ONLY 線形 kernel）：仕様の決定性と束縛（表・registry・D-1・f32 subset・plan・pseudo・W₂ identity・shard 表）と改変拒否；shard／sidecar／inventory の内容（formal key・UID 端・evaluation ID），fresh attempt 拒否，role 制限，batch 1 の 3 shard と rotation index，**配置と reference が同 latent**（同一 root で T 一致），**N₀ prefix の不変性**（短い生成が長い生成の prefix；chunk 非依存），改変 array／sidecar／partial の拒否。
