## C. pseudo 範囲 sub-partial と再開（`step1_engine/d4c1_subpartial.py`；`d4c1_partial.calibrate_family_partial(_rows=…)`；`run_reader.verify_run_references(pseudo_index_offset=…)`）
- **sub-partial**＝`calibrate_family_subpartial(..., row_range=(start, stop))`：FULL の登録 pseudo 列（official では n＝2000）を受け取り，global 行 [start, stop) だけを同じ per-row 手続で評価する。archive へ置く record（parent family_result・pseudo_family_plan・three_position_result・12 位置 full Result）は **global の `pseudo_index`** を持つので，単一 process の run と content-addressed で同一。record は schema `family_subpartial_calibration_v1`／kind `family_subpartial_calibration`，`rows`（start・stop・n_total・n_rows・global 列 SHA・slice SHA），`thresholds.pseudo`（n＝2000・global SHA・`rows`・slice の T1／T2 値と SHA），`binding.subpartial_dependencies`（`partial_dependencies` を持たない → family partial の reader／combiner は拒否）。archive identity は kind・family・payload SHA・commitment・rows。
- **combiner**＝`combine_family_subpartials(reg, man, subs, archive)`：同一 family の sub-partial が [0, n) を **sorted・連続・重複なし・隙間なし** に敷き詰めること（duplicate／overlap／gap／範囲外／別 family を拒否），共通 identity（engine・source binding・mode・registry／manifest・W₂ context／asset・twelve asset・campaign・commitment・global 列 identity・fingerprint at_gate・plan object 要約・W₂ context ref・gate identity（mode／passed／required／registered／rules_binding／env 版）・registry ref）の一致，slice の連結が global 列 SHA に再 hash すること，を検査し，family partial（schema `family_partial_calibration_v1`）を組み立てる：per-pseudo status／diagnostics／manifest key を行順に連結，archive ref は最初に trigger した pseudo の位置で挿入（registry は最後）＝単一 process の挿入順，`binding.subpartials`（range・各 sub-partial の SHA／ref／gate identity）を provenance として付加。run reader（`verify_partial_record`）で再検証してから family partial identity で archive へ置く。
- **同等性の主張と試験**：同じ入力・同じ列で，単一 process の `calibrate_family_partial` の record と sub-partial 結合の record は `strip_subpartial_provenance` 後に **内容同一**（archive ref も同一・同順）；さらにその family partial を `combine_family_partials` に渡した sealed record は単一 process `calibrate_sealed` と provenance 除き同一（`test_subpartial_*`：2 通りの tiling，trigger が別 chunk に跨る列）。**chunk 順で乱数や summary が変わらない根拠**：bootstrap plan は登録 object（多重度固定）で pseudo に依存せず，per-row 評価は carried state を持たない（同じ入力 object・同じ plan object・同じ閾値 → 同じ record）。固定 1..2000 の集合は変えない（global 列 identity と tiling の検査）。
- **再開**：sub-partial 1 件＝durable な単位（自分の出力 directory＋archive＋run record＋launcher final record）。runtime 消失時に失うのは open な range だけで，その range を **新しい attempt** として再実行する（旧 record は退避；原本を上書きしない）。結合時に完了済み sub-partial は payload SHA・run reader（global offset）で再検証される。保存先（`OUT_ROOT`＝Drive の専用 folder）は bank／source／stage と分離し，入力 run root との交差は launcher の anchor policy が拒否する。
- 運用：script `--mode partial --row-range A:B`（REQUIRED 25：`G_row_range`；flag `D4C1_SUBPARTIAL_PASS`；`D4C1_PARTIAL_PASS` は常に False；`G_pseudo_identity_bound` は global SHA＝登録定数 ∧ slice SHA＝消費した slice），`--mode combine-family --family F --subpartial DIR…`（REQUIRED 20；全 sub-partial run が `D4C1_SUBPARTIAL_PASS` のときだけ `D4C1_PARTIAL_PASS`；出力は `d4c1_partial_<F>_record.json`＋archive：`--mode combine` がそのまま消費）。notebook：partial v0.3（`ROW_RANGE`・`OUT_ROOT`）・combine-family v0.1。

## D. 固定分母の成功不能証明（`step1_engine/infeasibility.py`）
- **代数**：登録集約（`calibration.calibrate`）は固定 n＝2000 で WilsonUpper((c+u)/n) を閾値（support .05／strong .01）と比較し，行の truth は `any_family_truth`（technical_fail＞True＞unknown＞False）。ある行で少なくとも 1 family の eligible truth が True か unknown なら，他 family の非技術的結果によらず c+u に 1 が加わる；technical_fail の行は較正を technical（usable 値なし）にする。`wilson_blocking_count(n, thr)`＝WilsonUpper(k, n)＞thr となる最小 k（n＝2000：support **81**（80 件 .04950693664126962 → 81 件 .050056823219945756），strong **12**（11 件 .009822062795201926 → 12 件 .010458448381508351）；監査値と一致）。証明済み blocking 行数 ≥ k なら，未評価行をすべて False と補完しても usable＝True は不可能（level ごと）。
- **certificate**（schema `calibration_infeasibility_certificate_v1`／kind `calibration_infeasibility_certificate`）：入力は行→証拠の map（`blocking_rows_from_screen`：全 level `unknown_or_technical`；`blocking_rows_from_statuses`：partial／sub-partial の evaluated eligible truths を level ごとに True／unknown／technical_fail／False に型付け；False の level は数えない）。同一行の複数証拠は統合（型の強い方；矛盾は拒否），範囲外・重複・不正 kind は拒否。level ごとに `proven_blocking_rows`（True＋unknown＋unknown_or_technical），`technical_rows`（別計数），`first_blocking_count`，`usable_true_impossible_by_wilson`，`wilson_upper_if_remaining_all_false`。**主張しないこと**：c／u／rate，未評価行の状態や技術的成功，`usable=False` の較正，partial／sealed の完了。既存 reader は kind／schema で拒否（試験済み）。
- **screen**（schema `position_envelope_screen_v1`；`envelope_screen_family`）——十分条件：非 E1 family で，登録 W₂ 判定に unknown の size が ≥1 あり True の size がない（W₂ は登録 context で固定・全 pseudo 共通）とき，各 surviving size について matched system の 3 position × 利用可能 prefix（N0・N4）の正確 hit 率 P＝`point_P(hits, N)`（`orchestrator._family_Q` と同じ float64 式；`exact_hit_rate` は同じ配列・同じ比較・同じ関数で数える）の包絡が **全 hit＞0 かつ max/min ≤ 2.0** なら，その size はどの N 選択（混合を含む）でも event-ratio trigger（`max(P)/min(P) > 2.0`）が True にならない（除算は単調：選ばれた 3 値の max ≤ 包絡 max，min ≥ 包絡 min → float64 でも比 ≤ 包絡比）；zero-hit trigger は正値性で排除；precision 未達は unknown，technical は TECH。全 size が条件を満たすと `position_state` は not-expanded か position-unresolved のみ，family plan は provisional（または technical），`derive_outcome` は全 level unknown（TECH 保持）。条件を満たさない行は **未判定**（False とは言わない；通常評価へ）。record は registry／manifest・W₂ context SHA と判定 checksum・各 size view の `input_fingerprint`・global 列 identity・行・閾値の厳密値・hit count・N・P・包絡・blocking 理由・source binding を持ち，`check_screen_record` が内部整合（P＝point_P(hits,N)・包絡・blocking・内容 SHA）を再検査する。
- 試験：Wilson 計数；合成 count の 2³ 混合 prefix 全探索（包絡成立 ⇒ 全選択で trigger False；同一 N だけでは不十分な例）；合成 bank で W₂ unknown を 1 size に与えた E2（全行 blocking ⇔ evaluator unknown）と E7（ratio 発火行は screen 未判定，evaluator は 12 位置へ；非発火行は blocking ⇔ unknown）の **行ごとの一致**；screen の P＝evaluator の `P_model`；certificate の計数・統合・矛盾・改竄検出・reader 拒否。
- 運用：`--mode screen --family F [--row-range A:B]`（第 1 波 intake・plan・view のみ；D-3b 不要；REQUIRED 20；flag `D4C1_SCREEN_COMPLETE`；notebook D4C2 screen v0.1：標準 runtime 想定 >10 GB；時間は未計測＝行あたり 9 config × 2 prefix の比較のみで，probe の per-row 評価より桁違いに軽い見込み），`--mode certificate --screen DIR… [--evaluated DIR…]`（どこでも実行可；env lock は REQUIRED 外；`D4C1_CERTIFICATE_COMPLETE`）。

## G. v0.2 の変更（監査 R-D4C2A-A／B／C／D・非 blocking）
- **A（screen の gate 集合）**：script の共通準備が mode の REQUIRED にない検査（`G_d3b_units_accepted`）を gate 辞書に入れていた。`setg`／`getg` により，その mode の信頼 REQUIRED inventory にない検査は `diagnostic_checks` へ記録し，gate 集合は REQUIRED と厳密に一致する（notebook の厳密な key 集合照合は緩めない）。script の screen run の **実際の record** を未改変の screen notebook attempt cell に渡す境界試験（正常受理・余剰 key 拒否・欠落 key 拒否）を追加。
- **B（certificate の入口）**：`_certificate_entry`：certificate 専用 preflight（pins／inventory／script の束縛・登録 grid・登録 D4C-0 W₂ context と pseudo 列・登録 twelve asset・commitment 形式；REQUIRED_CERTIFICATE 12）。Phase C packet・frozen loader・登録環境 HARD gate・`--mt`／`--phasec` を要しない（`--mode certificate` にそれらを与えると拒否）；消費側環境は `env_gate` に **metadata として記録**（`matches_registered`）し gate にしない。評価 mode（partial／screen）の環境 HARD gate は不変。正式経路に self-test switch は不要：sandbox でも `--mode certificate` は preflight を通過して source 認証まで進み（self-test screen は正式 source として拒否：self-test flag・N≠登録 N0／N_max），同じ sandbox で `--mode screen` は environment で停止する（対照試験）。
- **C（証拠認証）**：`_certificate` は source を **認証してから**行を admit する：run record（schema・complete・failures 空・その mode の信頼 REQUIRED inventory と gate 集合の一致・全 True（正式では env lock を含む）・formal／selftest flag・COMPLETE／PASS flag・attempt・campaign・commitment・**この run と同じ source binding**（inventory／script SHA・engine 版）・probe でない），published evidence（file bytes の SHA／bytes＝run record の記録；唯一の evidence），run record の summary＝文書（screen SHA・件数）。screen は `check_screen_record(formal=True)`（内容 SHA・W₂ 適用性・各 position の `bank_stages`＝記録 stage・P＝point_P(hits,N)・包絡・blocking／coverage flag・**正式には全 position で N0 と N4 の両方，N＝登録 N0／N_max，evaluation id の suffix＝position，完全被覆**）＋ `bind_screen_record`（registry／manifest SHA・W₂ context SHA と **各 case の replay-verified decision checksum**・列 identity と **各行の閾値の厳密一致**・登録 configuration id・family・campaign・commitment）。evaluated は `evaluated_rows_from_record`：published record と archive の **既存 reader**（`load_(sub)partial_record` の payload／identity，published＝archived copy，`verify_(sub)partial_record` with registered identities＋current source binding，列 identity＝登録）を通してから eligible truth を使う（監査の対照：unknown→True の re-stamp は archived copy との不一致で拒否；schema 違い・archive なし・列違いも拒否）。`check_certificate` は admit 済み行の **代数のみ**を再導出することを明記（証拠認証と分離）。
- **D（family 別集約と閾値）**：証拠は (row, family, level) で整合（同一 family の矛盾のみ拒否；screen の `unknown_or_technical` は同 family の evaluated unknown／technical_fail で精緻化），その後 row ごとに全 family を `any_family_truth` の優先（technical_fail＞True＞unknown＞False）で合成：`blocking`（いずれかの family が True／unknown／unknown_or_technical → c+u に 1；二重計数なし），`technical`（いずれかが technical_fail → 較正自体が technical；別計数），`possibly_technical`（screen 由来：別 family の True があっても TECH の可能性を消さない），`aggregate`。閾値は constructor／checker とも `{support: RULES.usable_support, strong: RULES.usable_strong}` との完全一致（順序含む）を要求。
- 非 blocking：Profiler の `__enter__` 途中失敗時は設置済み wrapper を rollback；record の `outside_segments` は「固定費＋行別保存（segment 外の archive put）」と明記し，inclusive の合算を禁じる注記；`envelope_screen_family` の rows は変換前に型検査；報告書の「実行 GO を求めない」記述は撤回（現在の依頼＝probe の実行 GO と整合）。

## H. v0.3 の変更（監査 R-D4C2A-C1／C2／D1・N-D4ENV-HISTORY-PIN-COMPLETENESS・bridge 比較契約；engine 0.111.0）
- **C1（certificate の信頼 run inventory；`d/d4c1_calibration.py::_certificate`）**：v2 までの `run_ok` は producer run record の `required_inventory` と `gates` を **互いに**照合していたため，両方から gate を抜く／env だけの inventory／両方に余剰 key を足す改竄を受理し，空の `attempt`・別 pins・別 profile も通していた。v0.3 では `trusted_inventory(run)` が **この script の固定定数**を producer の mode から選ぶ（`screen`→`REQUIRED_SCREEN`，`partial` で `subpartial False`＋`row_range None`→`REQUIRED_PARTIAL`，`subpartial True`＋2 要素の範囲→`REQUIRED_SUBPARTIAL`，`combine-family`→`REQUIRED_COMBINE_FAMILY`；それ以外は拒否），`required_inventory` はその定数と **順序込みで等値**，gate の key 集合＝定数，各 gate `is True`（self-test source のみ sandbox の `G_env_lock` False を許す），`profile == production_official`，`source` の inventory／script／pins／engine と top-level `pins_sha256`／`engine_version` が **この run と同一**，`probe`／`instrument` False・`probe_n` None，campaign／commitment，`attempt` に `attempt_id` と `launcher_lock_sha256`（正式：非空 id と 64 hex lock），mode の成功 flag（screen `D4C1_SCREEN_COMPLETE`／partial `D4C1_PARTIAL_PASS`／sub-partial `D4C1_SUBPARTIAL_PASS`／combine-family `D4C1_PARTIAL_PASS`）が正式では True，**他 mode の flag はすべて False**。publication／reader の検査は不変。
- **C2（screen の W₂ 要約の完全束縛；`infeasibility.bind_screen_record`）**：v2 までは各 size の `checksum` だけを登録 decision の checksum と比べていたため，checksum を保ったまま `trigger`／`B_final`／`validation_state` を書き換え re-stamp した record を受理していた。v0.3 では消費側が **認証済み context の replay-verified `VerifiedW2Decision`** を渡し（`w2_decisions`），`w2_triggers(family, sizes, decisions)` で再導出した `{trigger, validation_state, B_final, checksum}` と record の `w2` を **`typed_equal`（型を含む完全一致：bool≠int，int≠float，str≠bool；key 集合・list 長も一致）**で比較する；decision の欠落・checksum 文字列だけを渡す呼び方は拒否。self-test 経路も同じ比較。
- **D1（False 証拠の保持；`infeasibility.evaluated_rows_from_statuses`（旧 `blocking_rows_from_statuses`）・`evaluated_rows_from_record`・`infeasibility_certificate`）**：v2 までは両 level False の evaluated 行を (row, family, level) 整合の **前に**捨てていたため，同 family の screen の `unknown_or_technical` と検証済み False の矛盾を検出できなかった。v0.3 では **すべての評価済み行**を証拠として admit し（`n_rows`／`n_blocking_rows`／`n_false_rows`），`_merge_same_family` で同 (row, family, level) の False は screen の `unknown_or_technical` とも他の非 False とも **矛盾**（拒否）；集約では False は **決して数えない**（別 family の False は別 family の blocking と両立）。certificate は `rows` に admit 済み全行（`n_rows_admitted`），`n_rows_proven`＝いずれかの level で blocking または technical の行数，level ごとに `retained_false_rows`；`check_certificate` は両方を再導出。
