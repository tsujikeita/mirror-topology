## 1. 事象（trigger）
2026-10-06 08:23 JST，監査 GO（`D4C2a_0.108.0_audit_decision.json`：計測付き probe E2・N＝3，commit `4668b2e5…`）の実行で，partial launcher v0.3 の preflight（cell 1）が **環境 lock（launcher pre-check）で停止**した：`environment lock failed (launcher pre-check): {'python': ('3.13.16', '3.13.15')}`。Colab の既定 runtime image が 2026-10-05（probe 実行：Python 3.13.15）以後に更新され Python **3.13.16** になった。著者が Colab の「ランタイム バージョンを変更」で試せた唯一の代替「2026 年 7 月」runtime は Python 3.12 系で，pins の numpy 2.1.3 を導入したところ `ImportError: cannot import name '_center' from 'numpy._core.umath'` が出て動作しなかった（**この観察は，その runtime で pins 環境を再現できなかったという事実にとどまり，NumPy 2.1.3 と Python 3.12 の一般的な非互換の証明でも，3.13.15 がいかなる手段でも再現不能であることの証明でもない**）。著者が利用できた runtime では登録環境 3.13.15 を再現できなかったため，本 amendment を起こした。Python 3.13.15 と 3.13.16 は同一 minor の patch release（バグ修正）である。launcher は設計どおり停止しており（hard gate；notebook・source は無改変），self-test skip 等の迂回は行っていない。失敗した 2 回の preflight（画面・notebook）は「失敗した環境確認」として今回の試行とは別に保管する（監査の条件）。

## 3. 性質（rules §0.4）
- 種別：**実装環境の patch 版更新**（interpreter のバグ修正 release）。科学的設計・統計規則・閾値・seed・plan・入力の変更ではない。
- 閲覧済み情報の開示：本 amendment の時点で，登録 D-2W W₂ context の 9 case 判定（4 case unknown）と，probe（E2・先頭 3 行・3.13.15）の record（core truths False・eligible unknown・Q_matched 等）を著者と監査が閲覧済みである。amendment は結果に依存しない（環境が利用不能になったことだけが動機）。

## 4. 受入れ条件（監査の bridge 比較契約 `D4C2a_v3_0.110.0_bridge_comparison_spec.json`，schema `D4C2a_environment_bridge_comparison_spec_v1`；v0.1 の「全体 SHA 一致」を置換）
1. **固定 source の bridge probe**：commit `39082b641d8621989ae69a273f4e88e0c59673ba`（engine 0.110.0・inventory `7df1fb59…`）の bytes に固定した計測付き probe（E2・N＝3・`INSTRUMENT=True`・High-RAM・既定 runtime の Python 3.13.16）を 1 回実行する（監査 GO の唯一の項目；GO は他の commit に移らない）。
2. **科学的内容の完全一致**：登録 baseline probe（`registered_assets/d4c1/probes/20261005T100239Z_386d63207c/`，3.13.15，partial payload `057ae753…`）と新 probe で，**per-row record 15 件**（family_result 3・three_position_result 9・pseudo_family_plan transition 3）を **typed identity と global row** で対応づけ（family_result と plan transition は `pseudo_index`，three_position_result はその行の plan transition が size ごとに名指す SHA），content SHA と bytes が spec の値と **完全一致**し，欠落・余剰・重複がないこと；registry record は同一；残る archive entry は partial 自身の transition 1 件だけ（その SHA は変わってよい）。partial record の `required_equal_partial_fields`（schema・kind・mode・family・registry／manifest／W₂ context／asset SHA・sizes・fingerprints・thresholds・archive_refs・per_pseudo_status／diagnostics／manifest_keys・w2_context_ref・campaign・plan_objects・scope）は内容一致。**partial の payload SHA 全体と archive の SHA 集合全体の一致は要求しない**（engine／module と gate 環境の provenance が変わるため；監査の反例：engine 版だけ，または記録 Python だけを書き換えても payload SHA は変わる）。
3. **provenance／環境は別途検証**：新 record は自身の未改変 reader（`load_partial_record`＋`verify_partial_record(..., registered=登録 identity, current_source_binding=True)`）を **生成した固定 source tree 上で**通ること；baseline の gate 環境は登録履歴（3.13.15）に，新 record の gate 環境は現行登録環境（3.13.16）に，それぞれ **自分の epoch で**有効（gate 辞書全体の等値は要求しない；`environment_source: live_collected`，6 版の厳密一致，BLAS pool 規則）；新 run record は complete・failures 空・信頼 inventory 24 gate 全 True・probe（`D4C1_PARTIAL_PASS` False）・profile record（segments 3・missing_targets 空）。
4. **手続き**：照合は `d/d4c2_bridge_compare.py` v2（`--phaseb` に新 probe を生成した固定 tree（commit `39082b64…`，engine 0.110.0；その tree の driver から AST で取り出した `REQUIRED_PARTIAL` と実 file が producer provenance の基準），`--spec`，`--baseline` に登録 zip，`--new` に新 zip，`--expected-commit 39082b641d8621989ae69a273f4e88e0c59673ba`）で行い，報告 JSON（schema `d4c2_bridge_comparison_report_v2`：producer run record の信頼 inventory・source／lock／final／precheck／prelaunch／twelve gate・typed identity の per-row 15 record・profile 文書・自身 reader・環境の各 epoch）を，raw 結果・実行済み notebook・lock／final・profile とともに監査に提出する。原本は書き換えず，旧 record の再ラベル（engine 0.107／3.13.15 以外への）も行わない。**不一致が 1 件でもあれば停止**して差分分析に回す（結果を見ての再試行・事後的な許容誤差の導入はしない）。一致しても，承認されるのは「固定の先頭 3 行の環境 bridge」だけであり，screen／certificate／正式較正／N4・KDE-CI・12 位置の数値経路の承認ではない。
5. 新しい実行の環境 gate は 3.13.16 を**厳密一致**で要求する（旧 3.13.15 の runtime が戻っても，その run は gate で止まる＝二重登録を避ける）；登録済み run（3.13.15）の record は履歴として受け入れ，それ以外の環境（例 3.13.14・別 numpy）は拒否する（`tests/test_d4c2a.py::test_registered_environment_history_and_live_gate`：履歴 field の欠落／null／空／余剰／label 改変／amendment 名欠落の拒否を含む）。
6. 本 amendment 後に生成・受入れる record は `python: 3.13.16` を記録する；受入れ済み資産の再生成・再実行は要求しない（intake は bytes／配列 SHA を再検証する）。
