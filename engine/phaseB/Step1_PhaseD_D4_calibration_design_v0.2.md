4. **評価**：`build_w2_context(asset, cases, m=100, master_seed=20260912, dist=w2_exact, whitening_identity, expected_asset_sha256=SHARED_NULL)` ——登録 shared-null asset（iso K 6000・最大長 null B_max 1000・replicate bounds；file＋payload SHA 束縛）を再利用し case ごとの null 再生成・再 seed をしない。n_sub 2000／5000（m＝100 → 20／50 cluster）・3 seed・3 pair の max・exact POT W₂（`positions.w2_exact`：cost 有限性に加え POT の終了 metadata／警告を検査；迂回しない）・B＝200→1000 の同一 null prefix・最初の比較 200 vs 400・f64 primary で B_final・indicator 一致・相対 q99 変化＜0.05・seed spread ≤0.25・f32 は同じ B_final／prefix／subset／W に条件付けた実 f32 selection path（astype 代用なし；未測定 bound を 0 として通さない）。solver 異常・非有限・入力欠落は **技術 FAIL（例外；context を作らない）**，所定条件未達は **w2-unresolved（trigger unknown）** として区別し保存する。
5. **record**：case ごとの `d2w_case_<F>_<S>.json`（schema `d2w_case_record_v1`：manifest（payload SHA）・result（stored evidence：observed pairwise 値・block・subset・bounds・null copy・stop／validation／trigger；content SHA）・typed decision（trigger／state／reason／B_final／observed_hash／distance_kind／scope／checksum）・inputs（unit manifest SHA・bank identity f64／f32・matched root SHA・whitening identity・formal）・constants）と `d2w_context_record.json`（schema `d2w_context_record_v1`：context SHA・summary・case 要約・SHARED_NULL）。script は publication 後に **published record だけから `restore_w2_context` で context を復元し live context と一致することを REQUIRED gate（`G_records_restored`）とする**。

### F.2 family partial と combiner（R-D4DESIGN-D）
- **新 scope**：`calibrate_family_partial(...)`（schema／kind／stage を partial 専用；global usable を発行しない）は 1 family の全 surviving size・両 system・正式 plan・required 入力を要求；出力は per-pseudo eligible support／strong truth（priority technical_fail＞True＞unknown＞False），required technical status，position source，3 位置 parent，全 size 拡張 plan，必要な 12 位置完全 Result，local fingerprint 前後，plan／object 検証。core_only や任意 per-size 診断の truth を eligible truth の代用にしない；trigger した family は全 surviving size の 12 位置段階を完了。
- **現行 official の全 family guard（`require_all_families=True` 強制）は維持**し，partial を従来の global seal に見せない。
- **combiner**：E1／E2／E7／E8 の partial 各 1 件（missing／duplicate 拒否）を，共通 identity（campaign／execution policy・source lock・登録環境条件・rules・registry／context／asset 受入れ・**同じ pseudo 列 SHA と順序（row index の対応）**・target commitment）と family 別 identity（fingerprint・plan identity・local size／config 集合；attempt／path／時刻／RSS は不一致で可）を**固定 family-map の該当 slice** に照合；summary の自己申告でなく reader 相当の stage／binding・parent／position／plan／12 位置完全 Result の数値・状態再導出・missing branch・artifact 欠落・source／inputs 対応を検査；E1 は 12 位置扱いにしない。集約：pseudo p ごとに全 family の eligible truth を集め，技術 FAIL が無ければ any-family の既知 True を c，True なく unknown ありを u，**分母 n＝2000 固定**で WilsonUpper(c+u, n) を登録閾値（support 0.05／strong 0.01）と比較（family ごとの c／u／FWFSR／usable の平均や OR ではない）。
- **Phase E 経路**：combined seal を `load_sealed_record`／`evaluate_sealed_target` の global kind／payload・参照鎖・current source binding・pseudo／input identity 検査に通す reader を設計し，partial の直接入力は拒否。D4C-3 で source 版や pins が更新されても履歴 lock／receipt の値は書き換えない。
- **同等性・拒否試験**：同一の人工 bank・plan・pseudo・W2 context で，既存単一 process と partial＋combiner の per-pseudo eligible truth・adaptation／stage・required failure・c／u／n・Wilson・usable・保存完全 Result の内容一致（全 True／False／unknown／technical，W₂ のみ／event-ratio のみ／zero-hit／非 trigger／全 size 12 位置／未完 branch／任意診断失敗）；拒否：pseudo 順序違い・欠落／重複 row・別 commitment・別 family／size／plan／source・missing／duplicate family・壊れた archive／re-seal 矛盾・stale success・partial の直接 target 利用。数理不変の実証前に「amendment 不要が検証済み」とはしない。
### F.3 required FAIL と任意診断（R-D4DESIGN-E）
- 「技術 FAIL 1 件で較正 FAIL」は **required quantities／必須入力／必須 branch** に適用する（`threshold_evaluator` の standalone per-size Q／KDE／CI は任意診断；その技術 status は required 結果を独立に veto しない）。required 技術 FAIL は他 family の True で打ち消さない；artifact 欠落・非有限を unknown に下げない。精度／W₂ 安定性由来の unresolved は固定 n で保守的に unknown 集計し，技術的成功でも `usable=False` になり得る（新 pseudo／seed を引く理由にしない）。
- record：`technical_failure`（process 失敗／中断）と `scientific_unusable`（計算完了・unusable）を別 field；技術 FAIL 時も診断・失敗 record を保存し有効な較正値を発行しない。再試行は旧 attempt・元 input／seed／plan・結果を見た時点・原因・旧新 source SHA・影響範囲を保存（rules §0.4：数理不変の実装修正／設計変更の別と，新データでの確認要否を記録）。
